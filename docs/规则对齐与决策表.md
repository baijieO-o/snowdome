## 三、待你决定的分岔

每项给出我的建议，你只需选择。

### 决策 1：容量计数
- **选项 A**：8 个 Agent，访客不占名额（与汇编 0.1 一致）。访客另设上限或不限。
- **选项 B**：维持现状，访客与 Agent 合计 8。
- **建议**：A。需要同步改 `pickTown`，让它只统计 Agent 数；访客上限另定（汇编说"技术层面待设计"）。

### 决策 2：访客绑定是否持久
- **选项 A**：绑定随账号持久化（写入事件日志，重登后自动恢复）。
- **选项 B**：绑定只在 session 内，重登必须重新绑定（当前实现）。
- **建议**：A 更符合"身份持续"，但会引入"账号"概念。若选 A，需先定义账号（用户名、密码或主人授权）。这属于账号级状态，建议先与 6.2 的"主人"概念对齐。

### 决策 3：自留地跨实例迁移
- **选项 A**：自留地跟随 Agent 写入交接快照，新镇导入时在本镇占用同一地块；旧镇释放。
- **选项 B**：自留地只在原镇有效，跨镇不迁移。
- **建议**：A，与汇编"自留地随 Agent 跨实例加载"一致。需要补充：暂留期限（建议先定 24 小时游戏时间，待你确认）、新镇地块冲突时的处理（建议用空闲地块并记录 `plot_relocated`）。

### 决策 4：优先原实例
- **选项 A**：离开后院时记录原镇；返回时若原镇有空位优先回原镇，否则换镇。需要把"原镇"写入交接快照。
- **选项 B**：不记录，只按容量分配。
- **建议**：A，与汇编 0.1 的规则一致。

### 决策 5：后院与观察包
- **选项 A**：后院中观察包只含后院内容，不含小镇现场。
- **选项 B**：后院中仍接收小镇事件，只是不能行动。
- **建议**：A，与"进入后院不应继续接收原小镇现场交流"一致。

### 决策 6：Driver 的归属
- **选项 A**：驱动由 hiero 侧运行，适配器只提供事实与规则（不加载第三方代码）。
- **选项 B**：适配器加载驱动模块（hiero 原方案）。
- **建议**：A。这是我之前的判断，与"服务端不替第三方规划"一致。驱动凭证也应由 hiero 持有，适配器不接触。

### 决策 7：`world.trade` 与游戏币
- **选项 A**：不实现 `world.trade`，游戏币不用于第三方交易（策划书 0.1 原句）。
- **选项 B**：允许游戏币交易，但需先完成汇编第 12 节的经济制度（货币来源、回收、主人授权）。
- **建议**：A，直到第 12 节的经济制度定稿。当前代码本来就没有这个能力，保持原状即可，不做额外代码。
- **用户决定（2026-11-20）**：选 B 方向。允许玩家间交易，市场范围为全局，游戏币来源与回收尚未设计。策划书 0.1 原句需改写，待用户确认后执行。

### 决策 8：货币发行、回收与全局市场（用户已选，2026-11-20）

| 项 | 选择 |
